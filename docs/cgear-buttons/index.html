Custom C-Gear buttons

Draw a button. Recognize a tap. Ask the game to do something it already knows how to do.

A worked Pokeweb example · BW2 runtime 0.5.6 · Updated 17 October 2026

Before you start #

This guide builds three custom buttons: REPEL, PC and PARTY. You will follow a complete reference implementation from its graphics archive to its native game events, then change a design and produce a separately named ROM. No AI assistant or browser button editor is needed to follow the lesson.

You should already have PMC code injection set up, understand variables, conditions and functions, and recognize files such as NARCs and overlays. You do not need to know C++ yet; chapter 3 explains the small amount used in the examples.

Choose the right game profile

The main walkthrough targets English US revision-0 Black 2 (IREO) and White 2 (IRDO). A compatible hack must preserve the checked interfaces. Black/White use a separate adapter; their addresses, graphics and request structures cannot be substituted into this walkthrough.

What you will have at the end

  • A compiled three-button design and a test ROM made from your own input ROM.
  • A clear route through drawing, touch ownership, native events and cleanup.
  • A way to add a button for another already supported key item.

The reference package also contains skins, a 12° skin dial, visibility flags and other actions. You do not need to implement those features to understand a button. We keep their production code intact so the lesson uses the same tested lifecycle as the actual patch.

1. The moving parts #

A C-Gear button has three separate jobs. Its artwork determines the pixels you see. Its hit test decides whether it owns a touch. Its action adapter translates that press into a native game event or a saved toggle.

AUTHORDesign + pixelslabel, color, action, position
→
COMPILEPrivate NARCconfiguration + sprite data
→
RUNTIMEDraw + hit-testone pending request
→
GAMENative eventopen, finish, return

We attach sprites to the native C-Gear's existing render unit. We intercept selected lifecycle and input calls, let the original game code run where required, and add our work around it. We do not replace the entire bottom-screen engine.

2. Build the three-button lesson #

Start with a known working result, then read how it is built. The lesson uses the complete source in this repository as scaffolding. It is a source-based build exercise, not a claim that the short teaching snippets alone form a complete replacement runtime.

Prepare the tools

From the Pokeweb repository root, install its locked Node dependencies and the Python build dependencies. Use the ARM GNU toolchain's arm-none-eabi programs and a compatible CTRMap/RPMTool JAR. Checkpoint

Cold-boot the new ROM with a copied ordinary save in which C-Gear has been obtained. You should see REPEL, PC and PARTY. A loaded emulator state restores its old runtime, so it is not a reliable test of a new build.

3. Just enough C++ #

The native runtime is freestanding C++17: it runs inside the game without a normal desktop C++ library. Most of the code is structs, integer calculations and function calls.

Notation Read it as
u8 / u16 / u32 Unsigned 8-, 16- and 32-bit integers. Width matters in binary records.
Subscreen* subscreen A pointer to a native subscreen object, not a copy of the object.
subscreen->heap Read the heap field through that pointer.
&request / *pointer Get an object's address / access the value at an address.
nullptr No object or no event.
struct A group of fields. Native request layouts must keep the correct order and size.
extern "C" Keep a predictable exported name for PMC's hook symbols.
#define CG_PLAY_SOUND … A named address alias. The compiler sees the same number after preprocessing.

For example, this is a real wrapper from game_state.inc:

C++ · native Party count 
u32 count(void* gameData) {
    return api<u32 (*)(void*)>(CG_PARTY_COUNT)(party(gameData));
}

u32 (*)(void*) describes a function that takes one pointer and returns a 32-bit integer. api<…> turns a checked game address into that callable function type. party(gameData) supplies the pointer to the native Party object.

api() resolves the verified ARM9 profile; ov() resolves a verified overlay address. In this BW2 adapter they set the Thumb address bit. Neither helper discovers a function's signature or loads an absent overlay. A wrong type, calling mode or overlay can crash even if the number looks reasonable.

at<u8>(pointer, offset) reads a known byte field at a byte offset; at<u32> accesses four bytes. It is our small replacement for missing native structure declarations. Offset knowledge lives at the adapter boundary—do not invent offsets when adding a button.

One source file, several readable sections

The .inc files are included by quick_actions.cpp, in order, and compiled together once. Do not compile each .inc separately. This organization preserves the existing private function names, native layouts and initialization order.

4. Give a button its pixels #

The buttons are sprites, also called actors in this code. The compiler draws them programmatically from indexed pixels. Text comes from decoded native glyphs, reduced to five pixels high, with black lettering, a colored outline and an outer black border. PC and PARTY use a ring sampled from the native artwork.

32 × 32pixels per button
4 bpptwo pixels per byte
512 bytesone visible sprite pose
4 posesnormal · active · pressed · unavailable

A 32×32 image contains sixteen 8×8 tiles. At four bits per pixel, each tile is 32 bytes. The DS expects those tiles in tile order, not a flat desktop-image row order. Here is the complete packer used by the compiler:

Read the actual pixel-to-tile function
compiler.ts · tile() 
export function tile(pixels: Uint8Array): Uint8Array {
  const out = new Uint8Array(512);
  let at = 0;
  for (let ty = 0; ty < 4; ty++)
    for (let tx = 0; tx < 4; tx++)
      for (let y = 0; y < 8; y++)
        for (let x = 0; x < 8; x += 2)
          out[at++] =
            pixels[(ty * 8 + y) * 32 + tx * 8 + x] |
            (pixels[(ty * 8 + y) * 32 + tx * 8 + x + 1] << 4);
  return out;
}

Know which resource does which job

Resource Purpose
Character pixels Which palette index each sprite pixel uses. The private archive stores raw four-pose banks for runtime composition.
NCLR palette Converts those indices to DS colors. A transparent pixel is an index/OBJ rule, not a desktop alpha byte.
NCER cells Describes sprite size, placement relative to its center, tile reference and palette bank.
NANR animation Selects a cell for an actor. These custom actors hold a frame while the runtime uploads the required pose.

The private archive is quick-actions/ui.narc. Members 1–3 hold palette/cell/animation resources, 4–11 hold eight four-pose banks, and member 12 holds ten native interior patterns. Member 0 is configuration; member 13 is editable metadata; member 14 backs up the original native character/cell pair. Later members contain the skin catalog and skin data.

The native BW2 C-Gear archive is a/2/8/7. We modify members 16 and 17, backing up their originals. The compiler losslessly repacks native sprite data to make room, then applies the owned control artwork changes. Unrelated native backgrounds and palettes stay in their original members.

Palette banks 7–14 belong to the eight custom buttons; bank 15 stays available to the native network resources. Eight visible poses need 4 KiB of sprite characters and 256 bytes of palettes. Their four-pose source banks take 16 KiB in CPU memory. The dial marker reserves another 128 sprite bytes. The compiler checks total sprite/OAM capacity for the loaded ROM.

To change a button from a circle to a square, start in circles.ts and the pose-generation code in compiler.ts. PC/PARTY also have a special native-ring path there. Change the hit shape in hit() and the editor preview's hit test to match the new artwork. Changing only the pixels leaves a circular clickable region.

5. Join the native lifecycle #

A hook redirects a particular game call or callback to our function. A hook address is a RAM address in a named module, not a byte offset in the ROM file. PMC's relocation records identify the module so an address reused by another overlay is not patched accidentally.

Our hook What we add
QaCGearInit Read the configuration; run native C-Gear initialization.
QaGearUnit Reserve extra actor slots while retaining the original 84.
QaCGearUpdate Run native update, attach resources once ready, update our state.
QaInput / QaButtonHit Resolve touch priority and capture a pending request.
QaCGearEvent Give native events priority, then dispatch our accepted request.
QaGearEnd / QaCGearExit Release our actors and retained buffers before native teardown.

build.py checks the original instructions, emits the hook stubs, compiles the C++ and converts the relocatable ELF to a PMC DLL. For a call-site hook, its generated symbol has a name such as THUMB_BRANCH_LINK_79_0x21ec980. Callback-pointer replacements use FULL_COPY entries. The exact register preparation and original call targets are part of the checked builder.

Draw at the right time

attach() borrows the native sprite unit and allocates our actors, character handles, palette and animation handles. A scheduled display task runs upload(). It composes the requested pose and native interior pattern into a retained main-RAM buffer, then calls the native upload routines.

Keep the upload source alive until the display system has consumed it. A local stack array may live in DTCM, which the DS DMA engine cannot read. The runtime therefore owns an upload buffer; it does not pass temporary stack pixels to DMA.

Cleanup runs for both full C-Gear exit and inner screen reconstruction. A Party/PC return can rebuild the native C-Gear work without replacing the outer subscreen object. Releasing our actors before native destruction prevents stale pointers and duplicate sprites.

Read the real initialization and update hooks
C++ · QaCGearInit() 
extern "C" void QaCGearInit(Subscreen* subscreen) {
    dispose();
    session.sub = subscreen;
    session.attempted = 0;
    session.held = 0;
    session.pending = 0;
    session.palette = session.animation = session.markerChars = INVALID;
    for (u32 i = 0; i < 8; i++)
        session.chars[i] = INVALID;
    void* archiveHandle = archive(subscreen->heap);
    enabled = archiveHandle && config(archiveHandle, subscreen->heap);
    closeArchive(archiveHandle);
    pokenavEnabled = enabled && navConfigured(subscreen->heap);
    ov<void (*)(Subscreen*)>(CG_CGEAR_INIT)(subscreen);
}
C++ · QaCGearUpdate() 
extern "C" void QaCGearUpdate(Subscreen* subscreen, u32 active) {
    session.active = active;
    ov<void (*)(Subscreen*, u32)>(CG_CGEAR_UPDATE)(subscreen, active);
    // Let all native graphics finish allocating before taking spare capacity.
    // A failed attempt remains invisible and is never retried every frame.
    if (enabled && !session.attempted && subscreen == session.sub && subscreen->work &&
        at<u32>(subscreen->work, 0) == (overlayAddress(CG_CGEAR_IDLE_CALLBACK) | 1)) {
        session.attempted = 1;
        attach(subscreen);
    }
    refresh(subscreen, active);
    if (session.appliedSound) {
        session.appliedSound = 0;
        api<void (*)(u32)>(CG_PLAY_SOUND)(CG_SOUND_MENU);
    }
    if (active && safe(subscreen))
        prepareSkin();
}

6. Turn a tap into a request #

Do not open a native menu directly from the drawing function. The input hook records which button was pressed, and the field event hook later checks whether the game can accept that action.

Pseudocode · teaching outline, not paste-ready C++ 
on_touch_update:
    if the world is blocked: discard the request
    if a held press is already captured: wait for release
    if this is a new press:
        let priority native controls keep their touches
        find the topmost visible custom button
        capture its touch, even if it is unavailable
        if it is available: pending = button_array_index + 1

on_field_event_request:
    ask the original game for its event first
    take pending, then clear it immediately
    if native wins or the world is blocked: discard our request
    recheck visibility and availability
    dispatch the selected button's action

pending is a button slot plus one, not an action ID. Zero means no request. Once the slot is resolved, the dispatcher reads button.action. Several buttons may therefore share the same action without confusing their positions or identities.

For circular buttons, hit() checks dx*dx + dy*dy <= 16*16. It searches from the front of the visible layer order back toward the rear. The wrench and native pattern control keep priority. A hidden button releases its touch region; a visible unavailable button keeps its region and uses a dim pose.

Holding the stylus must not launch a new event every update. The held latch remains set until release. Wrench dragging and the skin dial also capture a gesture, so moving over another button cannot trigger it mid-drag.

Read hit-testing and the complete input hook
C++ · hit() 
int hit(u32 x, u32 y) {
    int wx = static_cast<int>(x) - 228, wy = static_cast<int>(y) - 144;
    int sx = static_cast<int>(x) - 208, sy = static_cast<int>(y) - 18;
    int px = static_cast<int>(x) - 200, py = static_cast<int>(y) - 180;
    if ((session.saveControl && px * px + py * py <= 100) || wx * wx + wy * wy <= 100 ||
        (x >= 104 && x <= 152 && y <= 24) ||
        (!session.dialControl && session.skinCount && sx * sx + sy * sy <= 256))
        return -1;
    for (u32 n = session.count; n > 0; n--) {
        u32 i = n - 1;
        if (!session.shown[i])
            continue;
        int dx = static_cast<int>(x) - session.positions[i].x,
            dy = static_cast<int>(y) - session.positions[i].y;
        if (dx * dx + dy * dy <= 256)
            return static_cast<int>(i);
    }
    return -1;
}
C++ · QaInput() 
extern "C" void QaInput(void* gearWork) {
    Subscreen* subscreen = session.sub;
    if (!session.active || !safe(subscreen) || subscreen->work != gearWork) {
        cancelDial();
        session.pending = 0;
        ov<void (*)(void*)>(CG_CGEAR_INPUT)(gearWork);
        return;
    }
    u32 x = 0, y = 0;
    bool down = api<u32 (*)(u32*, u32*)>(CG_GET_STYLUS_POSITION)(&x, &y);
    if (session.dialCaptured) {
        if (!down) {
            session.dialCaptured = session.held = 0;
            visible(session.marker, false);
            return;
        }
        if (at<u8>(gearWork, 0x2fe)) {
            cancelDial();
            return;
        }
        int angle = angleAt(x, y), delta = angle - session.dialAngle;
        if (delta > 18000)
            delta -= 36000;
        if (delta < -18000)
            delta += 36000;
        session.dialAngle = angle;
        int dx = int(x) - dial::centerX, dy = int(y) - dial::centerY;
        if (dx * dx + dy * dy >= 6400 && absolute(delta) <= 9000) {
            int movement = session.dialAccum + delta;
            while (movement >= dial::step) {
                stepSkin(1);
                movement -= dial::step;
            }
            while (movement <= -dial::step) {
                stepSkin(-1);
                movement += dial::step;
            }
            session.dialAccum = movement;
            moveMarker(x, y);
        }
        return;
    }
    if (session.drag < session.count) {
        if (down) {
            auto& p = session.positions[session.drag];
            p.x = clamp(x, 16, 240);
            p.y = clamp(y, 16, 176);
            place(session.drag);
        } else {
            savePositions(game(subscreen));
            session.drag = 0xff;
            session.pressed = 0xff;
        }
        return;
    }
    if (session.held) {
        if (!down) {
            session.held = 0;
            session.pressed = 0xff;
        }
        return;
    }
    if (api<u32 (*)()>(CG_STYLUS_JUST_PRESSED)()) {
        int mx = static_cast<int>(x) - 215, my = static_cast<int>(y) - 163;
        if (session.muteControl && mx * mx + my * my <= 100) {
            session.held = 1;
            session.pending = at<u8>(gearWork, 0x2fe) ? 0 : 254;
            return;
        }
        int px = static_cast<int>(x) - 200, py = static_cast<int>(y) - 180;
        if (session.saveControl && px * px + py * py <= 100) {
            session.held = 1;
            session.pending = at<u8>(gearWork, 0x2fe) ? 0 : 255;
            return;
        }
        int sx = static_cast<int>(x) - 208, sy = static_cast<int>(y) - 18;
        if (!session.dialControl && session.skinCount && !at<u8>(gearWork, 0x2fe) &&
            sx * sx + sy * sy <= 256) {
            session.held = 1;
            session.pending = 0;
            if (!session.skinRequest && !session.skinUpload) {
                u32 i = 0;
                while (i < session.skinCount && session.skinIds[i] != session.currentSkin)
                    i++;
                session.wantedSkin = session.currentSkin == 0    ? session.skinIds[0]
                                     : i + 1 < session.skinCount ? session.skinIds[i + 1]
                                                                 : 0;
                session.skinRequest = 1;
                session.skinFeedback = 6; // Six 30 Hz updates: a 200 ms pressed flash.
                api<void (*)(u32)>(CG_PLAY_SOUND)(CG_SOUND_MENU);
            }
            return;
        }
        // Keep the fixed wrench reachable even if a saved/custom button is
        // positioned over it. Native editing/exit always owns this region.
        int dx = static_cast<int>(x) - 228, dy = static_cast<int>(y) - 144;
        int i = dx * dx + dy * dy <= 100 ? -1 : hit(x, y);
        if (i >= 0) {
            session.held = 1;
            session.pressed = i;
            if (at<u8>(gearWork, 0x2fe))
                session.drag = i;
            else if (session.available[i])
                session.pending = i + 1;
            return; // Disabled buttons also own their circular touch.
        }
        int mx0 = int(x) - 215, my0 = int(y) - 163, px0 = int(x) - 200, py0 = int(y) - 180;
        bool reserved = dx * dx + dy * dy <= 100 || (x >= 104 && x <= 152 && y <= 24) ||
                        (!session.dialControl && x >= 31 && x <= 65 && y <= 35) ||
                        (session.muteControl && mx0 * mx0 + my0 * my0 <= 100) ||
                        (session.saveControl && px0 * px0 + py0 * py0 <= 100);
        if (session.dialControl && session.skinCount && !at<u8>(gearWork, 0x2fe) && !reserved &&
            onDial(x, y) && QaButtonHit(gearWork) < 0) {
            session.pending = 0;
            session.held = 1;
            session.dialCaptured = 1;
            session.dialAngle = angleAt(x, y);
            session.dialAccum = 0;
            session.dialTarget = session.skinRequest  ? session.wantedSkin
                                 : session.skinUpload ? session.preparedSkin
                                                      : session.currentSkin;
            moveMarker(x, y);
            visible(session.marker, true);
            return;
        }
    }
    ov<void (*)(void*)>(CG_CGEAR_INPUT)(gearWork);
}

7. Connect REPEL #

Our unlimited Repel action is a toggle, not an application launch. The dispatcher flips Options bit 12 using CG_REPEL_OPTION_MASK and plays the spray sound only when the toggle becomes enabled. The other Options bits are preserved.

Changing a bit does not automatically alter encounters. Two additional call-site hooks connect that preference to the native encounter system:

C++ · saved preference + native encounter hooks 
bool repel(void* gameData) {
    return enabled && repelPresent && (*options(gameData) & CG_REPEL_OPTION_MASK);
}
extern "C" u32 QaRepelStep(void* encounter, void* gameData) {
    if (repel(gameData))
        return 0;
    return api<u32 (*)(void*)>(CG_REPEL_STEP)(encounter);
}
extern "C" u32 QaRepelDepleted(void* encounter, void* gameData) {
    if (repel(gameData) && count(gameData))
        return 0;
    return api<u32 (*)(void*)>(CG_REPEL_DEPLETED)(encounter);
}

The first hook pauses the ordinary step countdown while unlimited Repel is enabled. The second supplies the non-depleted result to the existing encounter path when appropriate. The game's surrounding encounter logic still applies its native lead-level filtering. Ordinary Repel items and their remaining steps are retained and resume when the unlimited toggle is turned off.

enabled && repelPresent matters. If the patch is disabled or every Repel button is removed, the saved preference becomes dormant. It is not silently deleted, and loading a save does not replay the spray sound.

What makes this example different

PC and PARTY reuse a native event constructor. REPEL requires a saved preference and encounter hooks. A touch callback alone cannot provide its effect.

8. Connect PC #

PC enters native field script 10090. The native script event creates its own script/VM storage and manages the storage menus, windows and cleanup. We return that event to the field system; we do not draw a lookalike PC window ourselves.

The current implementation also skips the introductory PC messages. It first checks the copied script's fingerprint, then changes the entry code of this invocation's private VM copy. Ordinary PCs and the separate Porta PC shortcut keep their original script.

Read the complete PC adapter
requests.inc · storageEvent() 
void* storageEvent(void* sys, u16 heap) {
    void* event = ov<void* (*)(void*, u32, void*, u32)>(CG_CREATE_SCRIPT_EVENT)(
        sys, CG_STORAGE_SCRIPT_ID, nullptr, heap);
    if (!event)
        return nullptr;
    // The native constructor has already created an independently allocated
    // script and VM. Change only this invocation's entry code; its native
    // event retains ownership and frees the script, VM and windows normally.
    void* work = api<void* (*)(void*)>(CG_EVENT_WORK)(event);
    void* scripts = at<void*>(work, 4);
    void* vm = at<void*>(scripts, 4);
    auto* code = at<u8*>(vm, 56);
    if (code && at<u8*>(vm, 32) == code + 30 &&
        fingerprint(code, PC_SCRIPT_SIZE) == PC_SCRIPT_HASH) {
        // Field start, initialize logout state, call the unchanged storage
        // choice loop, quick PC shutdown, then ordinary field-event cleanup.
        static constexpr u16 entry[] = {0x2e,  0x28, 0x8020, 0,      0x28, 0x8021, 1,   0x04,
                                        0x2bc, 0,    0x132,  0x8021, 0x30, 0x2f,   0x02};
        for (u32 i = 0; i < sizeof(entry) / 2; i++)
            at<u16>(code, 30 + i * 2) = entry[i];
        api<void (*)(u32)>(CG_PLAY_SOUND)(CG_SOUND_PC);
    }
    return event;
}

Read this in three parts: create the native event; locate its owned VM/script; patch only a recognized entry and play the PC access sound. The entry[] values are script instructions, not ARM function addresses. The source's size/hash check is what makes that specific edit conditional on a known script.

The installer checks the native script in a/0/5/6, member 1244, for designs using PC. If a hack has replaced it, do not force our instruction offsets into the new script. Use a compatible adapter or remove PC from that design.

Cancellation remains a native event outcome. When a native application destroys and rebuilds the C-Gear's inner screen, QaGearEnd() releases our actors before that teardown, and the later update attaches them again.

9. Connect PARTY #

PARTY uses the native field-menu application path. The important part is ownership: the request must outlive the function that opens the menu. A stack-local request goes away too early.

  1. QaCGearEvent() allocates a parent event with a FlyWork work block, clears that block, and records action CG_ACTION_PARTY.
  2. flyEvent() fills its embedded MapRequest. For PARTY, native application call 0 selects the Party route.
  3. The native child application borrows that request while it runs. CG_EVENT_CALL_CHILD makes the parent wait for the child to finish.
  4. On return, the parent examines the native result. Field skills or item-related follow-up events are handed back to the appropriate native constructors.
  5. When the event finishes, native event ownership releases its work. C-Gear reconstructs through its ordinary lifecycle.
Three numbers with different meanings

The button's stable ID might be 5. Its custom action code is 16. The native Party application call is 0. They belong to three different systems; do not use one in place of another.

The same owned request adapter also handles BAG, Town Map and several usable key items. Its historical name FlyWork/flyEvent remains to preserve existing linkage, but it now covers these native application requests. The native Party menu remains responsible for party selection, Summary, cancellation and field-skill selection.

extern "C" void* QaCGearEvent(Subscreen* subscreen, u32 available) {
    void* native = ov<void* (*)(Subscreen*, u32)>(CG_CGEAR_GET_EVENT)(subscreen, available);

            requestWork->field = subscreen->field;

            requestWork->heap = subscreen->heap;
            requestWork->returnMode = subscreen->mode;
            requestWork->sub = subscreen;
        }

    }
    if (action > session.count || !show(action - 1, subscreen))
        return nullptr;
    void* gameData = game(subscreen);
    void* sys = system(subscreen);
    const auto& button = session.buttons[action - 1];
    action = button.action;
    if (!canUse(static_cast<u32>(&button - session.buttons), subscreen))
        return nullptr;
    if (action == CG_ACTION_REPEL) {
        u16* p = options(gameData);
        *p ^= CG_REPEL_OPTION_MASK;
        if (*p & CG_REPEL_OPTION_MASK)
            api<void (*)(u32)>(CG_PLAY_SOUND)(CG_SOUND_REPEL);
        return nullptr;
    }
    if (action == CG_ACTION_POKENAV)
        return navLaunch(subscreen);
    if (action == CG_ACTION_PC)
        return storageEvent(sys, subscreen->heap);
    if (action == CG_ACTION_SYSTEM_SHOP)
        return shopLaunch(subscreen);
    if (action == CG_ACTION_POKERADAR) {
        api<void (*)(u32)>(CG_PLAY_SOUND)(CG_SOUND_MENU);
        pokeradar(subscreen);
        return nullptr;
    }

            : action == CG_ACTION_DOWSING ? 5
                                          : 4,
            sys, subscreen->field);

    if (event) {

        clear(requestWork, sizeof(*requestWork));

            action == CG_ACTION_PARTY)

C++ · flyEvent() 
int flyEvent(void* event, u32* sequence) {
    auto* requestWork = api<FlyWork* (*)(void*)>(CG_EVENT_WORK)(event);
    void* sys = api<void* (*)(void*)>(CG_EVENT_SYSTEM)(event);
    void* field = api<void* (*)(void*)>(CG_SYSTEM_FIELD)(sys);
    void* gameData = api<void* (*)(void*)>(CG_SYSTEM_GAME_DATA)(sys);
    if (*sequence == 0) {
        if (!field)
            return 1;
        u32 action = requestWork->action, itemId = requestWork->item;
        bool hmFly = action == CG_ACTION_HM_FLY;
        bool hmOwned =
            !hmFly || item(gameData, CG_FLY_HM_ITEM_ID, ov<u32 (*)(void*)>(CG_FIELD_HEAP)(field));
        int member = isFlyMapAction(action) && hmOwned ? flyMember(field, gameData, !hmFly) : -1;
        clear(requestWork, sizeof(*requestWork));
        requestWork->member = member;
        requestWork->action = action;
        requestWork->item = itemId;
        bool formItem = action >= CG_ACTION_GRACIDEA && action <= CG_ACTION_REVEAL_GLASS;
        requestWork->map.system = sys;
        requestWork->map.field = field;
        requestWork->map.call = action == CG_ACTION_RECORDER              ? 12
                                : action == CG_ACTION_PAL_PAD             ? 9
                                : action == CG_ACTION_XTRANSCEIVER        ? 13
                                : action == CG_ACTION_MEDAL_BOX           ? 14
                                : action == CG_ACTION_BAG                 ? 2
                                : (formItem || action == CG_ACTION_PARTY) ? 0
                                                                          : 8;
        requestWork->map.user = requestWork;
        requestWork->map.data = reinterpret_cast<void*>(formItem ? itemId : 0xffffffff);
        ownedMap = &requestWork->map;
        void* child = ov<void* (*)(MapRequest*, u32)>(CG_CREATE_MENU_APPLICATION)(
            &requestWork->map, ov<u32 (*)(void*)>(CG_FIELD_HEAP)(field));
        if (!child) {
            ownedMap = nullptr;
            return 1;
        }
        // The child's initial application is already Town Map. PARTY origin
        // selects the native Fly map and native Fly return result, bypassing
        // an unnecessary party menu. Request storage belongs to this event.
        if (member >= 0) {
            requestWork->map.call = 0;
            at<u8>(api<void* (*)(void*)>(CG_EVENT_WORK)(child), 0x68) = member;
        }
        api<void (*)(void*, void*)>(CG_EVENT_CALL_CHILD)(event, child);
        *sequence = 1;
        return 0;
    }
    ownedMap = nullptr;
    if (*sequence == 1 &&
        (isFlyMapAction(requestWork->action) || requestWork->action == CG_ACTION_BAG ||
         requestWork->action == CG_ACTION_PARTY) &&
        requestWork->map.result == 2 && field) {
        FlyCheck check;
        ov<void (*)(void*, FlyCheck*)>(CG_BUILD_FIELD_MOVE_CHECK)(field, &check);
        bool flyMap = isFlyMapAction(requestWork->action);
        u32 skill = flyMap ? 4 : requestWork->map.selection;
        if (flyMap &&
            (requestWork->member == INVALID || ov<u32 (*)(FlyCheck*)>(CG_CHECK_FLY_USE)(&check)))
            return 1;
        // Recheck the HM after the native map returns; never consume or grant it.
        if (requestWork->action == CG_ACTION_HM_FLY &&
            !item(gameData, CG_FLY_HM_ITEM_ID, ov<u32 (*)(void*)>(CG_FIELD_HEAP)(field)))
            return 1;
        UseHeader header = {
            static_cast<u16>(flyMap ? requestWork->member : requestWork->map.pokemon),
            static_cast<u16>(skill), requestWork->map.zone};
        void* child = ov<void* (*)(u32, UseHeader*, FlyCheck*)>(CG_CREATE_FIELD_MOVE_EVENT)(
            skill, &header, &check);
        if (child) {
            api<void (*)(void*, void*)>(CG_EVENT_CALL_CHILD)(event, child);
            *sequence = 2;
            return 0;
        }
    }
    if (*sequence == 1 &&
        (requestWork->action == CG_ACTION_BAG || requestWork->action == CG_ACTION_PARTY) &&
        requestWork->map.result == 3 && field) {
        void* child = ov<void* (*)(u32, void*, void*)>(CG_CREATE_KEY_ITEM_EVENT)(
            requestWork->map.selection, sys, field);
        if (child) {
            api<void (*)(void*, void*)>(CG_EVENT_CALL_CHILD)(event, child);
            *sequence = 2;
            return 0;
        }
    }
    return 1;
}

Both PARTY and BAG play the native menu selection sound (1356) on an accepted launch. PARTY is unavailable for an empty party. Existing menu enhancements can still operate because the native menu is the one being opened.

bool canUse(u32 i, Subscreen* subscreen) {
    const auto& b = session.buttons[i];
    if (!show(i, subscreen))
        return false;
    if (b.check != 255 && ov<u32 (*)(u32, void*, void*)>(CG_CHECK_KEY_ITEM_USE)(
                              b.check, system(subscreen), subscreen->field) != 0)
        return false;
    if (((b.action >= CG_ACTION_GRACIDEA && b.action <= CG_ACTION_REVEAL_GLASS) ||
         b.action == CG_ACTION_PARTY) &&
        !count(game(subscreen)))
        return false;
    if (b.action == CG_ACTION_POKERADAR && !radarEncounter(subscreen))
        return false;
    if (b.action == CG_ACTION_POKENAV && !pokenavEnabled)
        return false;
    return true;
}

11. Keep the player's layout #

Configured coordinates are defaults. The player can rearrange buttons in native wrench mode, so the runtime stores each saved position against its stable button ID. Reordering a list or changing a label does not move that button in an existing save.

BW2 uses a checked 36-byte record in reserved C-Gear bytes 16–51: a marker containing the selected skin ID, eight {id, x, y} records and a CRC16. Native bytes 0–15 are retained. The record is written into the game's save data in RAM and reaches the cartridge/save file through normal native saving.

Hold L + R for one second in wrench mode to reset only the custom positions to configured defaults, once per hold. If you change defaults while testing on a save with an existing layout, use that reset before deciding the new coordinates were ignored.

Visibility flags are read-only

An optional flag can further restrict visibility. For example, add "flag": { "id": 1517, "when": "clear" } to show a button only while that saved flag is clear. "set" requires it to be set instead. The runtime and installer never toggle these visibility flags.

The default PC design uses hide flag 0x05ED (1517), verified unused in the checked retail script/entity data. A hack can repurpose it, so choose a flag your own project leaves unused. BW2 accepts saved flag IDs 1–3059; these bounds are not the BW1 bounds.

12. Build, install and test #

Rebuild native code only when C++/bindings change. A new label, color, coordinate or existing action can be compiled into archive data without rebuilding the ARM module. The lesson CLI compiles the supplied design and uses the already bundled native DLL.

The complete path is: C++ → ARM objects → relocatable ELF → PMC DLL, alongside design + native assets → private NARC + packed native sprite pair. The installer stages the DLL, data and shared music dependency together. It rejects conflicting hooks and incompatible native resources before committing the staged configuration.

If you inspect the four exported resources in CTRMap, their paths are:

  • patches/CGearQuickActionsW2.dll or the B2 variant: native hooks and behavior.
  • patches/BgmToggleW2.dll or the B2 variant: the imported shared music API.
  • quick-actions/ui.narc: configuration and owned sprite/skin resources.
  • a/2/8/7: native archive with only its owned character/cell pair replaced.

For a manual PMC project, all matching assets and dependencies must be staged together and the framework must recognize that DLL's RPM format. Do not mix an old four-button DLL with a new archive. For the lesson, use the CLI's complete exported ROM so the production installer performs the compatibility work.

Black / White differences #

The ideas carry over; the binary adapter does not. The separate US revision-0 Black/White implementation is in bw1.cpp, with profiles produced by configure_bw1.py and build_bw1.py.

BW2 walkthrough BW1 adapter
Game IDs IREO / IRDO IRBO / IRAO
C-Gear archive a/2/8/7 a/0/3/0
Menu request size 68 bytes 64 bytes
Native calls api()/ov(), checked B2/W2 profiles Native::…, independently bound B/W profiles and calling modes
Artwork Small custom circular sprites and native patterns Native skin-aware panel/circle/callout presentation
Controls Skin dial, music and Save replacements Native small controls and Power; no Save replacement

Do not apply the BW2 offset or Repel bit instructions to BW1. Follow its saved-record accessors and generated profile. The beginner lesson CLI deliberately rejects BW1 so it cannot produce a misleading half-port.

Troubleshooting #

Symptom Check first
Nothing appears C-Gear obtained state, enabled archive, the runtime DLL path, required shared music DLL, and allocation/error state.
Art is scrambled 4bpp tile order, NCER size/tile reference, palette bank, native repacking, and that DLL/archive formats match.
Button is missing Required item and optional visibility flag. An invisible button is different from a dim unavailable button.
Button launches repeatedly A held press is not latched until release, or pending was not cleared before dispatch.
Click works but return crashes Request storage went out of scope, the parent did not wait for its child, or screen cleanup retained stale actors.

Changes are absent after rebuilding The lesson uses bundled DLLs: run the native builder after C++ edits. Cold boot the correct exported ROM instead of loading an old emulator state.
