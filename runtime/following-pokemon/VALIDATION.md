Each profile packages a base field/event pair and a full riding/Surf field/event pair, sharing a small resident core and separate overlay-140 Options and overlay-167 battle-intro modules. Registry validation runs in the field module. The core retains object-code bounds, ARM9 event forwarding, and two bounded transition tokens. Packaged CPU checks verified native forwarding with no field, event-module unload, and token recovery after event-module BSS reset. The binary contracts, imports, hook anchors, and base/full variants passed on all four profiles at their listed releases. All four current packages passed full-package checks for conversations, scripts, recall, movement hold, lighting, drawing priority, land riding, Surf handoff, positioning, cycling, terrain, and teardown. A saved-state-derived render fixture checks a nearby NPC's foreground gap across follower bounce frames, and conversation tests check that an accepted follower talk plays the native dialogue-start cue exactly once. The scene tests retain the follower through audited sound-only opcodes, the live `PVPlay` cry child, ordinary Yes/No prompts, and both native dialogue-list display variants, while rejecting unrelated or stale child events. Native services and graphics submission were modeled; no game emulator was run.

The separate Options module passed hook-site and packaged menu checks for button/touch navigation, staged On/Off, Confirm/cancel, save-bit preservation, highlight, markers, and background styling. Stock installer checks for this release passed fresh base/full installation, enable/disable, removal, full-to-base conversion, and export/reopen. All four profiles passed fresh full installation and update from their immediately preceding alpha. The preceding release also exercised both variants' full installer lifecycle on all four profiles. The update checks preserved authored dialogue and exactly one copy of each of the five runtime modules. They also verified that base installs omit mount assets, converted ROMs strip mount payloads without renumbering unrelated file IDs, and unrelated Options text edits survive. Stock and White2Upgrade registry checks exercised packaged lookup, malformed-data rejection, and repeated load/unload cycles. These tests do not establish visual, audible, or live-heap behavior.

The battle-opening checks execute the packaged wrappers and original native opening procedures with graphics/UI services mocked. Both variants of all four profiles passed 216 repeated/eligibility cases for wild and trainer openings, opponent effects, one player sprite before fade-in, no player throw or send-out, both HP bars, waits, fallback, and flag consumption. Field-handoff checks passed 200 automatic-selection cycles per variant/profile, explicit slot zero, all five later slots, invalid slot values, visible-actor, identity, HP, Egg, battle-format, cancellation and script-admission cases. The automatic-selection regression fails against the preceding stock package. An isolated replay against a private RAM copy from the reported wild encounter used native party reads to confirm the actual healthy lead identity and accept automatic/explicit slot zero while rejecting later slots; no game frame advanced. Only a visible healthy slot-1 follower matching the actual local singles lead qualifies. Later party slots and unsupported formats retain native recall/opening. No party order or save data changes are made.

The [memory audit](MEMORY-AUDIT.md) measures **1,152 bytes** of battle-resident follower code/data/BSS on every profile: the unchanged **788-byte core** plus a **364-byte battle module** with no BSS, imports, or private heap allocation. Compared with the earlier core plus resident event bridge, this saves **4,300 bytes** in stock White 2, Black 2, and Italian White 2, and **4,520 bytes** in White2Upgrade. The event bridge contributes another 1,464 bytes only if overlay 12 or 36 remains loaded; Options targets overlay 140. Loader metadata, allocator overhead, stack, VRAM, native sprite allocations, and actual free battle heap are not measured.

The installer accepts data-edited ROMs whose audited hook sites, adapters, and follower archives still satisfy the profile contract. White2Upgrade additionally requires its audited expansion modules. The previous release passed the full web suite (1,433 tests, 3 skipped). This field-only fix passed all 49 focused follower tests, the TypeScript/production build, provenance, and privacy checks. Human acceptance remains open for battle transitions, Options, followers, shadows/lighting, land mounts, retail Surf in base, custom Surf in full, and repeated mount/dismount cycles. Cold boot each versioned export with a matching ordinary save; older save states retain earlier loaded code. See the [test map](TEST-MAP.md) and [human checklist](EMULATOR-CHECKLIST.md).
