# Following Pokémon runtime

Pokeweb's dedicated Following Pokémon page installs five PMC modules for each supported profile. Current bundled versions are stock White 2 **0.6.93-alpha**, stock Black 2 **0.6.48-alpha**, Italian White 2 **0.6.49-alpha**, and White2Upgrade **0.7.44-alpha**. Stock games support species 1–649; White2Upgrade supports through 1023. Each profile has its own pinned binary contract, runtime fingerprint, and save family. Italian White 2 uses Italian generic dialogue; authored dialogue and gifts remain editable in Pokeweb.

New installs default to the **base** package: grounded followers, L/R cycling, dialogue, effects, scene safety, and walking-gap positioning. The install-time **Riding and custom Surf** option selects the **full** field/event DLL pair and adds the Surf archive, appearance registry, rider art, and anchors. Base has no riding hook, A+B handler, custom Surf renderer, or mount asset payload; retail Surf remains available. The shared core DLL is identical between variants. An installed choice is locked until the runtime is removed and reinstalled. Previously combined alpha installations upgrade as full. Conversion to base strips the old mount payloads and names on export while retaining reserved zero-byte file IDs to avoid renumbering unrelated ROM files.

The field module owns a temporary follower actor, a 64-record movement trail, registry validation, effects, and conversations. The full variant also owns land riding and custom Surf. The battle-resident core contains object-code lookup, native event forwarding, and two small transition tokens. The event bridge and scene policy load only with their field/event overlays; the Options UI loads only with its menu overlay. No follower actor is saved. Menus, unchanged PC storage, signs, and safe stationary conversations retain the visible follower; unsafe scenes, ordinary battle openings, doors, and genuine actor conflicts recall it. Seamless map crossings should retain it. L/R cycles the visible party follower without reordering the party. In the full variant, A+B mounts a visible eligible follower; ordinary Surf prefers a Surf-capable selected follower, then the first non-Egg Surf knower in party order. The selected land follower returns after Surf. Repel continuation retains a follower or mount for either answer.

For local singles trainer and wild battles, a visible grounded follower in **party slot 1** remains out through the encounter transition and is already on the player’s battle platform. The opening skips the player’s ball throw, send-out effect, and “Go!” message while preserving the opponent’s introduction and the native battle setup. The actual battle lead must match that healthy, non-Egg party member. Automatic following and explicit L/R selection of slot 1 both qualify; the internal automatic-selection sentinel is not a party slot. Followers from later slots, hidden followers, mounts, and other battle formats retain the normal recall/opening; party order never changes. A separate 364-byte module targets only battle overlay 167. A transient bit in the current battle setup carries eligibility and is consumed after the intro; there is no saved flag, extra resident token, or field-runtime retention.

Each profile adds **FOLLOWERS: ON/OFF** to the sixth in-game Options row, localized as **SEGUACI: SÌ/NO** in Italian. The row uses the native menu font, row background and border, selection palette, markers, help window, and controls. Off is stored in reserved Options bit 11, so existing saves default to On. Changes are staged until Confirm accepts them; canceling restores the prior choice. Off suppresses grounded followers and riding and returns an active custom Surf ride to the retail mount while preserving Surf mode. The Pokeweb enable control remains a ROM-wide master switch: disabling it leaves the in-game row blank without changing the save bit. Removal restores the four owned Options text entries if they still match the installed text.

Recall holds directional input and defers the native field-script callback for 12 field updates on all four profiles. The follower's private recall image uses the light cyan and white of the send-out flash, pauses briefly, then shrinks into the existing ball effect. The cloned billboard retains its draw-enable and map-light bits and the follower's last submitted pose. The battle ball cue plays as the ball opens and when recall begins. The event resumes after recall; human cold-boot checks remain, especially at doors and scripted transitions.

Walking and mounted artwork use a draw-only depth correction to clear their native ground shadow. A follower north of the player remains behind the player after that correction for all four player facings; north, side, and stair policies are separate. The player-depth correction runs only for followers close enough to overlap the player and retains a four-world-unit foreground gap for nearby native NPCs. Follower conversations play the native NPC dialogue-start cue once. The player's map light selection is mirrored on follower and mounted artwork while preserving native scene colors. Drawn quads and light flags are restored after synchronous submission, leaving world position, collision, shadow anchors, saves, and the movement trail unchanged. Visual and audible acceptance is pending. A saved emulator state contains its old loaded code: cold boot a new export with the matching ordinary save.

All four profiles keep the one-pixel paired mount/rider stride going while stopped, without moving the ground shadow. Stock White 2 also alternates the mirrored front/back stepping pose for six-frame mounts, completing both feet while keeping asymmetric artwork and side-facing directions intact. Its emote bubbles use full pixel scale and place their visible tip one source pixel above the highest opaque pixel of the current follower pose, in the camera plane. The row bounds are measured once from the already loaded recall texture before GPU upload; no per-frame image scan or extra texture load is needed. The stock terrain draw hook targets the native grass renderer at field+0xc8, separately from the actor and shadow passes. The grass task guard accepts the real 4 MiB DS range and the additional 12 MiB only when the verified native DSi mode accessor confirms it. Its alignment and complete task-span checks remain enforced. Each current-tile grass quad covers its owning actor’s feet and stays behind a nearer player or follower. The clamp uses the native camera-facing plane depth, preserving the grass image and restoring its quad after submission. Previous-tile tasks, unrelated effects and NPCs keep their native ordering. Automatic left/right gaps use the artwork-based 0–6 units plus six units, capped at ten minus the absolute authored X anchor to reserve space inside the maximum dialogue envelope. Authored gaps remain absolute overrides. The stock runtime also clamps a follower's logical and visual pose to its selected dialogue reach after a partial native step, with wall, elevation, connected-trail and two-tile bounds intact. The appearance editor offers up, down, and shared left/right walking gaps from 0–12, plus rider X/Y adjustments for land and Surf mounts. The four-direction previews use ROM player artwork and respond to edits immediately. Values are authored in the workspace and installed in `following/positioning.narc`; the runtime reads just the selected 12-byte land row or 8-byte Surf row from ROM.

## Assets and authoring

Stock White 2 0.6.93 adds optional **Min X, Max X, Min Y, Max Y** to conditional dialogue and gifts in both packages. Each bound is independent, edges are inclusive, and the player's tile at interaction time must satisfy every enabled bound and the existing selectors. Blank fields impose no restriction; zero and negative coordinates are supported. Coordinates are signed 16-bit matrix tiles: X increases east, Y increases south. They match raw NPC X/Y placement records, not the zone-relative preview: add the preview's zone origin when converting a displayed position. A Zone ID narrows the coordinate test to that zone; Any zone applies the same bounds wherever the player interacts.

Both coordinate sections offer **Open in Events** for a valid nonzero Zone ID. It opens the Overworld Editor in a new browser tab with that zone's header selected, including shared event files. Clicking a tile in Events → Permissions shows **Local X/Y** and **Global X/Y (matrix)**; use the global values for follower conditions. For example, the Aspertia City zone-427 preview has origin (32, 704), so local (3, 5) is global (35, 709), and local X 2–6 / Y 5 becomes global X 34–38 / Y 709. Save dialogue or gifts, export the ROM, and cold boot the new export to use the rule.

Unbounded dialogue retains ABI 1 (text) or ABI 2 (animations), and unbounded gifts retain ABI 1 byte-for-byte. Bounded dialogue uses ABI 3 with 28-byte rows; bounded gifts use ABI 2 with 36-byte rows. Each row adds four signed 16-bit limits and a presence mask in reserved bytes. Mixed archives may contain unbounded rows. The runtime accepts every earlier format; rule order, dialogue chance, animation presets and the ten per-Pokémon gift claim slots are unchanged. Both archives still share the existing 4 KiB scratch page, so bounded archives fit fewer rows. Older installed packages must be updated before Pokeweb saves bounds. Other bundled profiles and external runtimes without an explicit tile-bounds capability keep the original controls.

Stock White 2 0.6.92 retains followers through all 28 pure audio script commands and their native sound events, including NPC item-received fanfares, music changes/fades, push/pop, ambience and cries. The field guard validates the eight music/fanfare callback types against the live game sound context; native playback, waits and completion run unchanged. The cry child retains its checked script ownership. Parent events, movement, warps, battles and field teardown keep their own guards. Base and full packages share this behavior.

Stock White 2 0.6.91 bounds temporary player/follower depth advances against nearby loaded static prop models with a four-world-unit clearance. The smaller 0.6.90 gap could collapse to the same native quantized Z value and let the player overwrite furniture. The prop's native rotated bounding volume reserves its foreground depth where it overlaps the sprite; the player and follower quads keep their projected images, and all submitted values restore after drawing. Prop loading, geometry, collision and shadows remain native. Trashcan scripts may record a recent Join Avenue activity through the audited synchronous command `0x2C5` while preserving the paused follower; the ordinary movement, event and teardown guards still apply.

Stock White 2 0.6.89 permits dialogue when a recent turn leaves the follower up to half a tile sideways inside the native target tile. Player and follower facings are independent: narrow front/back art remains reachable from the side, and side-facing art remains reachable from above/below. Forward reach, authored gaps, wall/height checks and bounded trail checks remain in force. This changes interaction admission without moving actors or changing artwork or default offsets.

The editor's asset workspace stores validated appearance data under `following/`. Species, form, gender, and shiny variants are independently replaceable. Imported PNG sheets have two columns (idle and step) and four rows (up, down, left, right): 64×128 pixels for 32-pixel poses or 128×256 for 64-pixel poses. Each pose has transparency and at most 15 opaque BGR555 colors. Explicit source mapping is required; the importer does not guess numbered forms. Gen 5 artwork and optional Gen 6–9 artwork, Surf mounts, and land-rider art are separate bundled resources.

Replacement artwork can depict another species: the supplied Brionne sheet is tested over Dewott (502), retaining Dewott's game identity. Native descriptor byte 7 must select mode 0 for 32×32 frames or mode 2 for 64×64 frames. Mode 1 selects a 16×16 quad and texture-frame window, cropping larger imported artwork even when the editor preview is complete. **Repair follower artwork** fixes affected installed rows without reimporting the image or duplicating texture resources. Apply the repair, export and cold boot with the ordinary save; an older savestate retains its cropped draw settings. `npm run following:verify-artwork-native -- CLEAN_BW2.nds` checks these retail size/material routines in isolation, without launching a game emulator.

The descriptor's animation selector must also match the replacement: byte 9 is 13 for six poses with mirrored right-facing art, or 14 for eight independent poses. Retaining the previous selector can read beyond a six-frame texture on right-facing poses, displaying pixels left by another follower with the current palette after L/R cycling. Imports, bundled construction and **Repair follower artwork** now synchronize both selectors from the validated size/profile. The native check exercises both layouts in every direction across repeated changes. `verify_artwork_state.py ROM.nds STATE.dst` independently checks the captured texture, palette and stale-pixel evidence; `scripts/repair-following-artwork-rom.ts` creates a separate repaired export while verifying unchanged artwork, executable modules and unrelated file IDs.

Stock Black 2 and White 2 both support **Apply follower artwork**. Preparation includes the external Gen 5 bundle, including all 624 normal/shiny/form/gender appearances for species 494–649. The retail appearance table lacks 103 of those species; its 422 Bulbasaur substitution rows are replaced by the bundled art in the prepared catalog. A private `following/bundled-assets.narc` makes these resources available for preview before installation without changing the retail model archives. Installation binds the bundled resources and imported overrides into the native descriptor/resource archives. Existing prepared catalogs migrate without losing imports or positioning edits, and installed catalogs supersede stale retail placeholder rows in the editor. Installation also repairs recognized older runtime catalogs that still point missing Gen 5 appearances at retail placeholders; explicitly imported artwork is preserved. Remaining fallback labels describe shared form art or normal-color shiny substitutions, rather than absent Gen 5 species. Italian and externally managed artwork application remain outside the stock BW2 apply path.

For an installed stock BW2 game, import a PNG or asset pack, click **Apply follower artwork**, export, and cold boot the new ROM. The artwork, registry, descriptor references, grounding, spacing, mounted rider anchors and ownership receipt update together. Runtime DLLs and saves are unchanged. `npm run following:verify-artwork -- ROM.nds` checks the base package; append `--riding` for full. The supplied 64×128 Dewott regression sheet is a test fixture, not a replacement in the default bundled catalog. `scripts/build-following-dewott-artwork-rom.ts` creates a separate export with that sheet assigned to all four species-502 appearance keys.

Conditional dialogue and one-time gifts live in follower-owned NARCs and can be edited without recompiling PMC code. Stock White 2 0.6.88 adds optional Before dialogue and After dialogue motions to each conditional rule: cry, hop, shake, rock, looking and directional shuffles. The twelve existing sequences retain their cry cues and restore facing and visual offsets. The post-dialogue motion plays after dismissal, before player movement resumes. Existing text-only rules default to None. These controls require an updated installed runtime and remain unavailable on unrebuilt profiles. Gifts have ten stable per-Pokémon claim slots; any number of ordered rules may reuse those slots within archive capacity. The installer accepts modified revision-0 ROMs when their audited code sites and follower archive layout still match; a whole-ROM clean SHA is not required. It owns its files by fingerprint, supports recognized alpha updates and enable/disable, and leaves authored data in place when disabled. Removal writes inert modules at the owned file IDs; shared PMC and imported assets remain.

## Build and checks

From the Pokeweb repository root, supply an exact pinned clean ROM:

```sh
npm run following:build -- /path/to/cleanwhite2.nds
npm run following:build-black2 -- /path/to/cleanblack2.nds
npm run following:build-italy -- /path/to/cleanwhite2-italy.nds
npm run following:build-upgrade -- /path/to/White2Upgrade.nds
npm run following:test
npm run build
```

Add `--publish` to a profile build to replace both bundled variant pairs and their receipt only after binary and packaged-code checks pass. `following:build-rom` installs the base package into a test ROM without launching an emulator; pass `--riding` for full. It copies the versioned alpha ROM to `Repos/` and preserves existing saves. Manual test output defaults outside this source tree. Python tooling uses `ndspy`, Pillow, Unicorn, Capstone, and `pyelftools`; the existing ignored `build/python` dependency directories remain supported. Set `ARM_TOOLCHAIN_BIN`, `RPM_TOOL_JAR`, or `FOLLOWING_BUILD_ROOT` when using nondefault local tools or output paths.

## Limits

Human timing, sound, terrain, stair, occlusion, crowded-map allocation, and long-session checks remain necessary. Unsupported binary signatures are rejected. Stock ROMs cannot use later-generation species or art. Imported resources do not imply that every form has unique artwork. Retail content and unrelated PMC patches require their own compatibility checks. No current-profile full game-emulator acceptance is claimed by the packaged ARM tests.
