# Trainer Customization

Install from **Code Injection → Infrastructure and Dependencies** or from **Tools** in the Trainer editor. Select a Pokémon in the trainer’s party, edit its settings, and export the ROM. Shiny, Pre-Dmg (starting HP, dragged on the HP bar or typed as an exact value) and Pre-Status appear below its moves. Supports US Black 2 and White 2 revision 0. The installer adds PMC as needed and upgrades the bundled Trainer Natures runtime, including the older inline ARM9 version.

Explicit natures use the existing one-based nature byte in the trainer Pokémon archive. Auto uses the game’s original nature. The new options apply to opposing trainers in standard local battles. A Pokémon can start at full HP, a percentage of its final maximum HP, or an exact value capped at its maximum. Percentages round down to a minimum of 1 HP. Sleep can use the game’s normal duration roll or a set duration of one to three turns. Toxic starts at its first damage stage.

Every roster a trainer can field has a tab above its party cards: **Original** (its own party), each alternate party, each pool it draws from, and other trainers' parties it borrows. Choosing a tab shows that roster's Pokémon in the same cards and slot editor. Each tab shows its share of battles; the selected tab's **Weight** sets it, and 0 leaves it to rules only. Removing every extra roster restores the original. Up to 32 rosters are available per trainer.

**+ Party** creates an alternate party of one to six Pokémon as a copy of the original, already in the random choice. Its Pokémon have their own settings; the arrows set their battle order. **+ Pool** creates a pool that starts with the original party as its candidates. **Link…** uses another trainer's party or an existing pool. Changes save as you make them. A party or pool that can't build a legal team shows a warning on its tab and stays unsaved in the editor; the ROM keeps its last working version.

Pools are shared across trainers. A pool's tab names the other trainers that use it and offers **Make a copy for this trainer**. A pool draws a party of one to six Pokémon from up to 32 candidates. Set the draw size, Lead and Ace slots, species rule and held item rule on the pool's tab, and tag each candidate in the slot editor. Candidates have their species, form, level, gender, ability, IVs, nature, held item, moves, shininess, starting HP and status. Leaving all four moves blank uses the level-up moves for that species and level. A candidate linked from another trainer's slot inherits its settings; **Copy into this pool** gives the pool its own copy. Moving a source Pokémon within its roster updates saved pool references. Remove a candidate from its pools before deleting its source slot. **Roll a team** draws a sample party the way the game does.

Under **Rules**, add rules in priority order. Each reads as a sentence, such as "If the player's party has Snivy, use Party B", and joins its conditions with and (all must match) or or (any may match). Each rule can choose between several rosters with weights. The first matching rule with an eligible roster takes priority. If no rule can supply a roster, the default weighted choices apply. A rule that is missing a Pokémon or roster stays unsaved until it is complete.

- **The player's party has** checks whether the party contains a species. Forms share the same species ID.
- **The number of** counts Pokémon with the chosen type in either type slot. Each matching Pokémon counts once.
- **The highest level in the party** compares the chosen threshold against the highest level in the party.
- **The player's starter** checks the saved slot chosen from Bianca. It applies after receiving the starter, including after the starter leaves the party.

The party conditions use the player's saved party. Eggs are excluded and fainted Pokémon count. An empty eligible party has no highest level.

On a trainer with variations, Test battle fights the roster shown, or the game's own pick when chosen beside the button. Trainers with variations have a die beside their name in the trainer list.

The **Lead** tag reserves the first party positions and **Ace** reserves the last positions. A pool can use up to one of each or up to two of each. When both tags are present, the pool reserves at least one of each if the party size allows it. A one-Pokémon party uses a Lead when available, then an Ace, then an untagged candidate. Additional tagged slots are used when a legal team can fill them. Untagged candidates fill the middle. Species rules can allow duplicates, require different species IDs, or permit different forms of the same species. The held item rule allows any number of Pokémon without an item and accepts a list of item IDs that may repeat. Pokeweb rejects a pool if its tags and clauses cannot produce a party of the requested size. [Trainer Party Pools in pokeemerald-expansion](https://rh-hideout.github.io/pokeemerald-expansion/tutorials/how_to_trainer_party_pool.html)

Set **Draw mode** to **Per slot** to give each party slot its own slot pool, Pool A through Pool F. Add candidates to slot pools in the Pokémon editor. Several slots can draw from the same slot pool, and each candidate can belong to several. The game shuffles the candidates separately for each slot and uses each candidate at most once in the completed team. It applies the species and held item rules across all slots. A slot pool with one viable candidate fixes that slot's Pokémon. The editor keeps the last valid pool until every slot can be filled together. The **Lead / Ace** mode uses the tag settings described above.

**Move alternatives.** Each move slot can list other moves it may use instead. Press **+** beside a move and type one; each choice has a weight, and the slot's own move is a choice too (weight 0 leaves it out). In battle, the game rolls one move per slot by weight before the Pokémon enters. A move never appears twice: a roll that would repeat one starts over, and slots without alternatives keep their moves. After 16 tries the Pokémon keeps the moves it was built with, and the editor warns when the slots can't all get different moves. Picking one of a slot's alternatives as its move swaps the two. Party cards with varying moves show a die. Alternatives apply to the trainer's own party, to alternate parties and pool Pokémon of their own, and to pool candidates linked from a trainer slot (which use that slot's alternatives). Test battle rolls them like the game; Showdown text lists the slots' own moves.

The game chooses once per opposing trainer when it builds a standard local trainer battle. The selected roster or pool supplies the party size and Pokémon. The trainer being fought supplies the identity, battle format, items used by the trainer, AI, dialogue, and rewards. The game uses each source slot directly. It draws pool members without replacement and keeps the selected team for that battle. During a battle, choices with too few Pokémon for the required lead positions are skipped. The original roster is used when none qualify.

The versioned NitroFS file `battle/trainer-customization.bin` has a 16-byte header followed by six six-byte member records per trainer ID. The header fields are the four-byte `PWTC` signature, 16-bit version 1, 16-bit member record size, 32-bit trainer count, and a reserved 32-bit zero. Members store shininess, status, sleep turns, and HP mode as single bytes, followed by a 16-bit HP value. All integers are little-endian. Zero-filled members inherit the normal battle setup.

The roster file `battle/trainer-rosters.bin` uses the four-byte `PWTR` signature, 16-bit version 1 and entry size 6, followed by 32-bit trainer and entry counts. The directory has one 32-bit entry index per trainer plus the final index. Each entry stores a 16-bit roster source, a 16-bit weight, an 8-bit party size, and an 8-bit reserved zero. Roster sources are trainer IDs or authored party IDs with bit 15 set. IDs 1–255 identify shared pools and IDs 256–16383 identify fixed alternate parties. Pokeweb validates references and refreshes pool data and party sizes from the exported archives.

The conditional file `battle/trainer-roster-rules.bin` uses the four-byte `PWRC` signature, 16-bit version 1, a reserved 16-bit zero, and 32-bit trainer and payload byte counts. The directory stores byte offsets relative to the payload, with a final offset marking its end. Each rule starts with the condition count, roster count, match mode (0 for All, 1 for Any), and reserved zero, all single bytes. A condition stores its kind and comparison as bytes, then its subject and value as 16-bit integers. Kind order is species, type count, highest level, starter slot. Comparison order is equal, unequal, less than, at most, greater than, at least. The rules use the same six-byte roster entries as the default table.

The pool file `battle/trainer-party-pools.bin` has a 16-byte header with the four-byte `PWTP` signature, a 16-bit version, a 16-bit member entry size, 32-bit pool directory count, and 32-bit payload byte count. The directory contains one 32-bit payload-relative byte offset per pool ID plus the final offset. ID 0 is reserved. Each row starts with one byte each for party size, member count, species rule (0 off, 1 species, 2 species and form), held item clause (0 off, 1 on), maximum slots per tag, held item exception count, selected lead count, and selected ace count. The next six bytes are a validated fallback team's candidate indices in party order, padded with zeros, followed by two reserved zero bytes. Then come the 16-bit held item exceptions and the candidate entries. Each candidate has a 16-bit source trainer ID, one byte with the slot in bits 0–2 and the tag (0 untagged, 1 lead, 2 ace) in the upper bits, one byte for the native party format, and 16-bit species, form, and held item IDs. The runtime uses the fallback team if the randomized search reaches its work limit.

Version 1 uses 10-byte entries and stores linked candidates. Version 2 uses 28-byte entries and supports both kinds of candidate. A zero trainer ID and slot identify a pool-owned candidate. The 18-byte extension stores IV difficulty, packed ability and gender, level, and nature as single bytes, then four 16-bit moves and the six-byte member settings. For linked candidates the extension is zero. Pokeweb writes version 1 for linked-only pools and version 2 for pools with their own Pokémon.

Version 3 retains the 28-byte entries and uses row header bytes 14–15 for the owning trainer ID of a fixed alternate party. Shared pool rows keep these bytes zero. A fixed row contains only its own Pokémon in party order, has identical member and party size counts, and has all species, item and tag rules disabled. Its fallback indices are in slot order. The game loads that order directly, including when the party was selected by a weighted choice or conditional rule.

Version 4 uses 29-byte member entries. It adds six group bytes after each row header and before the item exceptions. A per-slot row uses group numbers 1–6 for its party slots and zeros for unused slots. The row's lead and ace counts are zero. The all-zero group array preserves ordinary pools and fixed parties. Byte 28 of each member is its membership mask with bits 0–5 for groups A–F. The runtime tests group membership alongside the shared duplicate constraints and uses the validated fallback if the randomized search reaches its work limit.

The move alternative file `battle/trainer-move-pools.bin` has a 16-byte header: the four-byte `PWMP` signature, 16-bit version 1, 16-bit key size 8, 32-bit key count and 32-bit payload byte count. Keys follow in ascending order of source and index. Each key stores a 16-bit source (a trainer ID, or a party or pool source with bit 15 set), an 8-bit party slot or pool candidate index, a zero byte and a 32-bit payload-relative offset. Each entry stores four alternative counts (up to 15 per slot and 32 in all), four 16-bit weights for the slots' own moves, then each slot's alternatives as a 16-bit move ID and a 16-bit weight from 1. Linked pool candidates use their source trainer slot's key. Pokeweb keeps the entries with their Pokémon when party slots move and when parties and pools are saved.

Run `python3 runtime/trainer-customization/build.py` to rebuild the two DLL assets and compatibility manifest. The build uses the trainer nature assembly, US revision-0 ROMs, GNU ARM tools, ndspy, and CTRMap’s RPMTool. `ARM_TOOLCHAIN_BIN` and `RPM_TOOL_JAR` override the tool paths.
