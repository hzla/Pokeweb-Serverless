# Native item effects

US revision-0 Black, White, Black 2 and White 2 support adjustable item recipes
and bounded AND/OR conditions. BW2 also supports native handler assignments and
code/data parameters. Presets are editable starting
points; authoritative controls and formats are in `src/pokeweb/itemEffectsModel.ts`,
`itemRules.ts`, `itemRulePresets.ts` and the native profile catalog. Other regions/revisions require separate verified profiles. BW1 retains each
item’s original behavior until custom effects are applied; copied native item
handlers, Drive/Plate typing and trap-switch adapters remain BW2-only.

New custom drafts start empty. Import Effect Template appends effects to the
current draft and combines activation conditions with AND, preserving nested OR
groups. Existing values and the consumable setting are retained. Imports that
exceed the editor bounds leave the draft unchanged. A first import into an empty
item draft adopts the template's consumable setting. Apply custom effects commits
the resulting composition.

Shared native code parameters affect all users of that implementation; item-data
parameters remain per item. Composed rules support up to 16 effects, native
callbacks, trigger/target/chance settings and per-effect state. Native behaviors
retain their intrinsic restrictions. Fling, Natural Gift and bag-use routing stay
in item data; reward, breeding, evolution and field effects are outside this
in-battle library. Drive/Plate move typing does not reproduce form/ability systems.

Maranga Berry, Weakness Policy, Fairy Feather, Roseli Berry and Safety Goggles are
editable templates. Their primitives expose grouped hit-triggered stat changes,
typed move-power multipliers, type-resistance damage ratios, weather immunity and
move-class immunity. Resistance berries use a multiplier of damage taken: 0.5×
halves damage and 0.25× quarters it. Existing resistance berries offer **Customize
resistance**; Chilan defaults to also working on neutral Normal hits. Original Fairy effects require a Fairy-enabled ROM. Vanilla imports use Normal;
the resistance template then accepts neutral hits. Select another existing type
in the effect’s controls as needed. All templates accept the ordinary AND/OR conditions.

Heavy-Duty Boots, Clear Amulet, Covert Cloak, Loaded Dice, Mirror Herb and Punching
Glove (power) are also available as templates. Controls select protected hazards
or stats, additional status/stat/flinch effects, a multi-hit minimum, copied stats
and stage multiplier, and boosted move class/type/category. Punching Glove does
not remove contact. Boots cover the three retail hazards (Spikes, Toxic Spikes,
Stealth Rock), preserve Poison-type Toxic Spikes absorption and use native factor
skip checks. No Sticky Web engine is installed. Loaded Dice affects native 2–5-hit
moves; fixed-count and per-hit-accuracy move mechanisms retain their native rules.
Mirror Herb measures actual opposing positive stage changes, including capped
and large boosts, during an entry/action/held-item check and copies the group once, then consumes once. It does not copy reductions
or recursively mirror boosts generated by this primitive. Stat caps and native
stat-change rules still apply. A reusable composition can copy later boost groups.
Clear Amulet uses item prevention text; Covert Cloak silently prevents additional
effects while primary effects remain active. Prevention and copying notices follow
[pokeemerald-expansion](https://github.com/rh-hideout/pokeemerald-expansion), with
native BW message variants and the actual holder/item names.

Effects sharing one event finish before a consumable is removed. Prevention
recipes act on qualifying native checks, before the engine’s chance roll; they
do not predict whether that roll would have succeeded. Maranga's forced berry use
runs through native temporary-item events; the item recipe does not change whether
the item's actual identity is classified as a berry. Move-class immunity uses stock,
recognized expanded-move defaults and available ability move-class overrides when
item rules are applied. Reapply item rules after changing those classifications.

All custom rules share `patches/ItemEffects.dll`. The builder verifies the loaded
ROM's callbacks and dependencies and relocates each selected copy once. Unknown
code and conflicting hooks are rejected before installation. Consumability applies
to the whole item; failed conditional activations retain it. AI/preview queries
restore private state and do not consume items.

Resident code/data/state is bounded to 64 KiB, with a separate 112 KiB loading
budget and checked 16-bit RPM offsets. The existing PMC loader still requires
compatible ARM9 bindings. Metadata supports project/ROM reopening and recognized
legacy migrations; changed templates/dependencies are checked again on reopen.

Build with `python3 runtime/item-effects/build_rules.py` (`--legacy` for v3 and
`--v4` / `--v5` for the retained v4/v5 templates). New rules use version 6; older templates stay
available for exact verification of existing exports. Native catalog generators require explicit local reference inputs.
Run `npx vitest run src/test/itemEffectsModel.test.ts src/test/itemRules.test.ts src/test/itemRecipes.test.ts src/test/itemTemplatesPortable.test.ts`
for model checks. Native fixture builders write separate outputs; emulator tools
require melonDS and `MELONDS_HEADLESS_LIB`. Representative native cases do not
establish hardware, DSi or all cross-patch combinations.
